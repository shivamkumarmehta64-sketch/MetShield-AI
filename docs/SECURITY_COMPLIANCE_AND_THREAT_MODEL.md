## 1. Executive Summary & Security Posture

MetShield-QMS is a critical national infrastructure (CNI) telemetry quality assurance system serving the Ministry of Earth Sciences (MoES) and the India Meteorological Department (IMD). Because atmospheric observations directly influence Numerical Weather Prediction (NWP) models (NCMRWF GFS/WRF), disaster evacuations (NDMA/IMD cyclone warnings), and military aviation safety, telemetry data integrity is an imperative of national sovereignty.

MetShield-QMS enforces a **Zero-Trust Edge Security Model** across all data ingress points, edge transformation pipelines, and visualization layers.

```
       [ AWS Field Station / IoT / DCP ]
                       │  TLS 1.3 + HMAC-SHA256 Packet Seal + Nonce
                       ▼
       [ Cloudflare Edge / Vercel Edge Shield ]
         ├─ L3/L4/L7 DDoS Scrubbing (Anycast)
         ├─ Token Bucket Rate Limiting (120 req/min per Station ID)
         ├─ Strict Schema & Geographic Geofence Boundary Check
         └─ Content Security Policy (CSP Level 3) + HSTS (preload)
                       │
                       ▼
       [ MetShield-QMS Edge Runtime Engine ]
         ├─ Cryptographic Verification of Packet HMAC
         ├─ Merkle Audit Root Computation
         ├─ Multi-Parameter Physical & Storm Discrimination
         └─ WMO No. 8 Standardized Quarantine
                       │
         ┌─────────────┴─────────────┐
         ▼                           ▼
  [ IMD NWP Ingestion ]       [ Operator Console & Mobile ]
  (Validated Data Stream)     (Encrypted Session / RBAC)
```

## 2. Threat Modeling (STRIDE Analysis)

| STRIDE Category | Specific Threat in AWS Telemetry Network | Severity | MetShield-QMS Countermeasure & Architecture Defense |
| :--- | :--- | :---: | :--- |
| **Spoofing (Identity)** | Malicious actor injecting rogue weather packets masquerading as IMD Station `AWS-DEL-04` to trigger false cyclone panic. | **HIGH** | Station-specific pre-shared keys (PSK) generating HMAC-SHA256 signatures per packet. Hardware station identity verified against geo-coordinates. |
| **Tampering (Data)** | Man-in-the-Middle (MitM) altering barometric pressure or temperature readings in transit over cellular GPRS or satellite DCP. | **CRITICAL** | End-to-end TLS 1.3 encryption. Cryptographic HMAC packet seal covering `{stationId, timestamp, rawT, rawP, rawH, classification}`. Tamper detection marks packet invalid. |
| **Repudiation** | Operator or remote technician denying modification of station calibration parameters or manual anomaly overrides. | **MEDIUM** | Append-only audit logs with Merkle root hashes (`auditMerkleRoot`) and immutable sequence counters in the Diagnostic Register. |
| **Information Disclosure** | Leakage of sensitive station metadata, internal IP addresses, or observer communication logs. | **LOW** | No personally identifiable information (PII) collected or stored. Strict sanitization of headers; server tokens stripped at reverse proxy. |
| **Denial of Service (DoS)** | Volumetric HTTP flood targeting `/api/telemetry` or `/api/weather` to overwhelm serverless runtimes and drop real-time storm packets. | **HIGH** | Cloudflare Edge Anycast DDoS scrubbing + Cloudflare Workers Cache / Vercel Edge CDN with `s-maxage=15..60, stale-while-revalidate=120`. Stale cached data served if upstream is degraded. |
| **Elevation of Privilege** | Attendant field technician accessing national NWP bypass controls or overriding WMO Flag 4 alarms without authority. | **HIGH** | Role-Based Access Control (RBAC) separating "Observer / Technician" (view only, run bench calibration) from "Senior Duty Meteorologist / Admin" (quarantine release, master override). |

## 3. Zero-Trust Cryptographic Data Integrity Engine

Every packet ingested or generated by MetShield-QMS carries a cryptographically verifiable security seal:

```typescript
export interface SecuritySeal {
  hmacSha256: string;        // 32-byte hexadecimal hash of payload + secret key
  antiReplayNonce: number;   // Monotonically increasing / timestamp-derived nonce
  auditMerkleRoot: string;   // Merkle tree leaf hash for block integrity
  geofenceStatus: 'VERIFIED_IN_BOUNDS' | 'GEO_ANOMALY';
  tamperStatus: 'AUTHENTIC' | 'SIGNATURE_MISMATCH' | 'REPLAYED';
}
```

### 3.1 HMAC-SHA256 Signature Specification
1. The datalogger creates a raw signature string:
   $$\text{RawSig} = \text{StationID} \parallel \text{Timestamp} \parallel T \parallel P \parallel RH \parallel \text{Classification}$$
2. The payload is signed using an HMAC hashing function seeded with the IMD network master key or per-station secret.
3. If an adversary alters any float value (e.g. changing $T$ from $32.1^\circ\text{C}$ to $52.1^\circ\text{C}$), the calculated HMAC diverges, immediately tripping `FLAG_4_CORRUPT_HARDWARE` with `tamperStatus = SIGNATURE_MISMATCH`.

### 3.2 Anti-Replay Nonce Enforcement
To prevent replay attacks (capturing a genuine severe thunderstorm packet from 2024 and resending it during clear skies in 2026):
- Each packet must have a valid UNIX timestamp within $\pm 300\text{ seconds}$ of edge clock.
- Nonces are tracked in an in-memory/KV sliding window; identical timestamps for the same station are rejected.

## 4. Network & Application Security Controls

### 4.1 Transport Layer Security (TLS)
- **Minimum Version**: TLS 1.3 required; TLS 1.0, 1.1, and 1.2 legacy ciphers disabled on Edge endpoints.
- **Cipher Suites**: `TLS_AES_128_GCM_SHA256`, `TLS_AES_256_GCM_SHA384`, `TLS_CHACHA20_POLY1305_SHA256`.
- **HSTS**: `Strict-Transport-Security: max-age=63072000; includeSubDomains; preload`.

### 4.2 HTTP Security Headers
All Next.js and Cloudflare Worker routes emit hardened headers:
```http
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(self)
Content-Security-Policy: default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline' fonts.googleapis.com; font-src 'self' fonts.gstatic.com data:; img-src 'self' data: https: blob:; connect-src 'self' https://api.open-meteo.com https://cloudflareinsights.com;
```

### 4.3 Rate Limiting & Edge Shielding
- **Ingestion Endpoints (`POST /api/telemetry`)**: 60 requests per minute per IP / Station ID. Burst allowance of 10 packets. Exceeding requests receive `429 Too Many Requests`.
- **Read Endpoints (`GET /api/weather`)**: Edge CDN cached with `s-maxage=15`. 100,000 requests per minute absorbed directly at the Cloudflare/Vercel edge point-of-presence (PoP) without executing backend compute.

## 5. Geofencing & Physical Boundary Verification

India's sovereign territory spans from $6.7^\circ\text{N}$ to $37.1^\circ\text{N}$ latitude and $68.1^\circ\text{E}$ to $97.4^\circ\text{E}$ longitude.
- Every station packet contains station metadata.
- If incoming telemetry claims GPS coordinates outside the station's surveyed benchmark monument or outside the official Indian sovereign boundaries, the system automatically triggers `GEO_ANOMALY` and quarantines the stream.

## 6. Regulatory & Government Compliance

### 6.1 GIGW v3.0 (Guidelines for Indian Government Websites)
- Meets mandatory Indian government digital safety standards.
- Fully accessible to screen readers, supports high-contrast viewing, and features bilingual Hindi/English operation.

### 6.2 CERT-In Cyber Security Directions (2022)
- Synchronized with National Physical Laboratory (NPL) / Indian Standard Time (IST).
- Tamper-evident logging with timestamps recorded in both ISO 8601 UTC and IST (`Asia/Kolkata`).
- Architecture facilitates incident reporting within mandated 6-hour windows in the event of unauthorized telemetry tampering.

### 6.3 Zero PII Footprint (DPDP Act 2023 Compliance)
- MetShield-QMS operates strictly on meteorological atmospheric observations and station engineering metrics.
- No citizen data, private emails, phone numbers, or passwords are stored, ensuring zero risk under the Digital Personal Data Protection Act 2023.
