# Architecture & Design Spec: MetShield AI (SIH 26073)

## 1. Project Overview & SIH Alignment
**SIH Problem Statement 26073** focuses on Automatic Weather Station (AWS) telemetry quality, specifically distinguishing between genuine extreme weather events and hardware faults (WMO Pub No. 8 compliance). 

This design upgrades MetShield AI into a premium, Google Weather / Material You-inspired system, while deeply integrating 5 core India Digital Public Infrastructure (DPI) APIs. These integrations are not just tacked on; they form a cohesive, end-to-end storyline for the judges.

## 2. The Core Workflow (The SIH Demo Story)
1. **Edge Anomaly Detection (AIKosh):** An AWS sends a suspicious reading (e.g., massive pressure drop). The anomaly logic uses models pulled from **AIKosh** to flag it: *Is this a cyclone or a broken barometer?*
2. **Historical Validation (Data.gov.in):** The Ops Console automatically queries **Data.gov.in** for historical climate baselines in that district to see if this pressure drop is statistically possible.
3. **Field Tech Dispatch (Bhashini & DigiLocker):** A Field Node app user is dispatched. They unlock the node using **DigiLocker** (verifying they are a certified IMD technician). The diagnostic UI is translated seamlessly into their local language via **Bhashini**.
4. **Resolution & Payout (Setu):** The tech replaces the sensor, verifies the fix, and signs off. **Setu** API is immediately pinged to process the vendor payout/contractor fee for the repair. 

## 3. UI/UX Design System ("Google Weather" / Premium Material)
The visual overhaul ensures the app looks like a flagship ecosystem, moving away from "hackathon functional" to "production premium."

**Color Palette (Semantic Tokens):**
*   **Base:** Soft surface colors. Light mode uses off-whites (`#F8F9FA`), Dark mode uses deep navy (`#0B132B`).
*   **WMO Status Colors (Critical cross-app consistency):**
    *   Nominal / Good: Emerald (`#10B981`)
    *   Convective/Weather Event: Blue (`#3B82F6`)
    *   Sensor Drift (Warning): Amber (`#F59E0B`)
    *   Hardware Fault (Critical): Rose (`#EF4444`)
*   **Typography:** Moving to a clean sans-serif like `Outfit` or `Inter` for modern readability. Tabular nums for all telemetry data.

**Key Layouts:**
*   **Ops Console (Desktop):** A dense but breathable glassmorphism dashboard. Large map in the center. Floating metric tiles. Data-heavy but visually separated by soft shadows and generous border radii (`16px`/`24px`).
*   **Field Node (Mobile):** High-contrast OLED dark mode. Large touch targets (`min 44px`). Bottom-sheet drawers for diagnostics.

## 4. API Integration Architectures (How we wire them in time)
To build this rapidly, we will integrate via frontend facades and Next.js Route Handlers.

*   **Bhashini:** Add a provider to `AppShell.tsx` that wraps strings. We will use a Bhashini translator mock/API route for the demo to auto-translate labels.
*   **DigiLocker:** Build a specific `<DigiLockerLogin />` UI component matching their branding that sits in the `GovTechnicianDrawer`. 
*   **Data.gov.in:** Build a `fetchClimateBaseline()` in our `lib/stationData.ts` that hits the open data API.
*   **Setu:** Add a `triggerRepairPayout()` action linked to the "Submit Fix" button on the Field Node.
*   **AIKosh:** Add a badge/status indicator showing the current XAI model version fetched from AIKosh inside the "Architecture" panel.
